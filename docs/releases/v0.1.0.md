# Portable AI Memory v0.1.0

**First public alpha: a lossless, user-owned memory core for AI conversations.**

Portable AI Memory separates personal AI memory from any single vendor. This release focuses on the foundation: preserve source conversations faithfully, index them for retrieval, reconstruct conversation branches, and expose the result through a small read-only MCP interface.

## Highlights

- **Lossless ChatGPT import** from `chat.html` or sharded `conversations-*.json` exports.
- **Branch-aware canonical storage** that preserves the full mapping tree instead of flattening only the visible/current conversation path.
- **Exact provenance** through stable conversation/message identifiers plus SHA-256 source hashes.
- **Fast local search** with SQLite FTS5.
- **Context packs** that return bounded, source-backed excerpts for a task instead of sending an entire lifetime of chats to an AI model.
- **Portable MCP access** with read-only tools for search, exact-message lookup, conversation retrieval, stats, and context-pack generation.
- **Self-hosting foundation** with Docker, a PostgreSQL/pgvector schema, and experimental cloud deployment scaffolding.

## Why the data model matters

Real ChatGPT exports contain node and message identifiers that are not guaranteed to be globally unique. Portable AI Memory scopes those identifiers by `conversation_id`, preventing records from different conversations from overwriting or joining to each other accidentally.

The importer also preserves branch points and the `current_node`, so the system can reconstruct the active conversation while retaining abandoned/alternate branches for provenance and later retrieval.

## Quick start

```bash
git clone https://github.com/chandanpandeys/portable-ai-memory.git
cd portable-ai-memory
python -m venv .venv
source .venv/bin/activate
pip install -e '.[mcp]'
python scripts/import_chatgpt.py /path/to/chat.html ./output
python -m memory_os.search ./output/memory.sqlite 'your query' --limit 10
```

Run the MCP server:

```bash
MEMORY_DB_PATH=./output/memory.sqlite python -m memory_os.mcp_server
```

## Privacy

The repository is public; your memory should not be. Do not commit exports, generated canonical data, SQLite/Postgres databases, tokens, `.env` files, or embeddings containing private content. The project defaults and contribution policy are designed around that separation.

## What is not in v0.1.0

This is intentionally a focused alpha. Claude/Gemini/Codex importers, incremental sync, semantic/vector ranking, temporal knowledge graphs, conflict detection, and the private management UI are roadmap items rather than claims of this release.

## Next milestone

`v0.2` focuses on **multi-source import and incremental ingestion**, starting with Claude, Gemini, Codex/session data, and a generic importer interface.
